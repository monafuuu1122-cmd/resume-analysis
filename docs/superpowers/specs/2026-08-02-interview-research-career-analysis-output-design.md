# 面试研究、岗位方向分析与输出净化设计

## 目标

在不破坏旧 JD、旧面试研究和旧岗位方向记录的前提下，完成三项升级：

1. 面试研究不再因单条来源标签或证据引用错误而整份失败。
2. 岗位方向基于联网检索得到的主流招聘职责，逐条映射个人档案并解释匹配原因，同时列出需要补充的能力与岗位思维。
3. 页面不再显示内部证据 ID、模型分析过程、Schema 错误 JSON 等技术内容。

本轮只交付本地全真浏览器验收版，用户确认后再发布生产网站。

## 面试研究容错链路

保留现有企业搜索、网页读取、千问归纳和研究版本存储流程，在模型输出与正式 Schema 之间增加服务端净化层：

- 移除不存在的 `sourceIds` 和 `evidenceClaimIds`。
- `official` 洞察没有引用官方来源时，按现有来源降级为 `public`；只有推断依据时降级为 `inference`。
- `match` 能力没有候选人证据时改为 `unknown`，不得伪造证据。
- 单项无效内容被过滤或降级时，研究状态为 `partial`，其他已完成内容照常保存。
- 只有模型服务、鉴权、网络或完全不可解析等任务级错误才返回失败。
- API 只返回稳定错误代码与中文提示；Zod issue、堆栈和原始上游响应不得进入 UI。

## 岗位方向联网分析

为每个岗位方向增加可版本化的市场岗位画像。生成时输入：岗位名称、可能职位名称、用户全部有效档案证据、已保存偏好；联网检索主流招聘页面和可靠职业资料，归纳 6—10 条常见职责或能力要求。

每条映射包含：

- 市场常见要求；
- 来源摘要与链接；
- 对应的个人档案事实摘录；
- 匹配原因；
- 匹配状态：优势、基本匹配、证据不足、明显短板、待确认；
- 建议准备方式。

页面按“市场要求逐条对照”“需补充能力”“需建立的岗位思维”“信息来源”展示。个人经历只展示与当前要求相关的短摘录，不整段复制。没有匹配证据的要求也必须保留，并进入能力或思维缺口。

旧岗位方向继续使用现有本地分析；用户点击“生成新版岗位分析”后才写入新的联网分析记录。联网失败不会覆盖上一次成功结果。

## 输出净化

内部证据 ID 继续用于数据关联，但不作为可见文本。服务端提示词明确禁止输出推理过程、内部字段名和括号式 ID；展示层再统一清除遗留的 `claim-*`、`profile-material-*`、`span-*` 等标识。正常语义括号，例如职位英文名或行业缩写，不做无差别删除。

## 测试与验收

- 单测覆盖官方标签降级、未知来源过滤、局部成功保留与安全错误映射。
- 单测覆盖岗位市场要求逐条映射、短摘录、缺口分类和旧数据兼容。
- 单测覆盖内部 ID 不进入页面文本。
- 运行现有测试、类型检查与生产构建。
- 启动本地网站，使用真实千问和联网服务完成浏览器验收；不触发生产部署。
