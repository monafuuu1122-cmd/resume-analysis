# DeepSeek 全站迁移与岗位方向非联网分析设计

## 目标

1. 取消“岗位方向—市场岗位画像”的联网检索，改为由 DeepSeek 基于模型已有知识归纳常见岗位要求，并与用户档案逐条对照。
2. 全站 AI 生成服务从千问迁移到 DeepSeek，保留现有简历提炼、JD 分析、岗位匹配、企业研究、回答优化、模拟面试与复盘功能。
3. 避免在岗位分析中整段搬运用户经历，只展示短、准、可追溯的证据摘录。

## 模型与配置

- 使用 DeepSeek OpenAI 兼容接口：`https://api.deepseek.com/chat/completions`。
- 默认模型为 `deepseek-v4-flash`，兼顾响应速度和结构化分析质量。
- 生产环境密钥使用 `DEEPSEEK_API_KEY`，默认模型使用 `DEEPSEEK_MODEL`。
- 浏览器设置页提供 DeepSeek Key 与模型的手动填写入口；密钥只保存在当前浏览器，不进入备份、提示词或日志。
- 旧千问浏览器密钥不自动迁移为 DeepSeek 密钥，避免把不同服务商的凭证错误混用。
- 旧 JD、岗位方向、企业研究和模拟面试记录继续兼容读取。

## 统一 AI 服务边界

- 将当前千问专用客户端、错误类型和请求体命名收口为通用 AI/DeepSeek 服务。
- 简历提炼、能力归纳、JD 适配、岗位灵感、岗位方向分析、企业研究、回答优化、模拟面试、追问和复盘全部经过同一个 DeepSeek 服务端入口。
- 所有结构化任务使用 JSON Output，并在提示词中明确要求输出 JSON。
- 保留服务端超时、浏览器取消、错误分类、格式校验和局部重试。
- 错误文案统一改为 DeepSeek，不再出现千问、DashScope 或 QWEN 配置提示。
- 环境变量和错误码迁移为 `DEEPSEEK_*`；旧分析记录中的历史错误码仅用于兼容显示，不再产生新的 QWEN 错误码。

## 岗位要求与经历对照

原“市场岗位画像”改名为“岗位要求与经历对照”。该功能不调用任何搜索服务，不请求网页，不展示来源链接。

DeepSeek 输入包括：

- 岗位方向名称及可能岗位名称；
- 用户已确认的经历证据；
- 独立填写的技能与工具、AI 应用场景、证书和语言能力；
- 用户对岗位方向的状态和历史分析结果。

每项岗位要求显示：

1. 常见岗位要求；
2. 当前匹配状态：优势、基本匹配、证据不足、明显短板或待确认；
3. 用户档案中的 3—4 条对应证据；
4. 为什么匹配；
5. 准备建议。

证据展示规则：

- 每条只截取能证明匹配关系的关键句，不展示完整项目段落；
- 单条限制为约 60—90 个中文字符；
- 同一经历只在确有不同证明角度时重复出现；
- DeepSeek 只能引用输入中存在的原文，不得补写事实、数据或职责；
- 没有证据时显示“当前档案暂无直接证据”，不得用模型知识替代个人证据。

分析下方继续显示：

- 需补充能力；
- 需建立的岗位思维；
- 针对具体缺口的下一步行动。

匹配分数只根据可回溯的个人档案证据计算，不因为模型列出通用岗位要求而自动提高。

## 企业研究

企业研究不再联网搜索，由 DeepSeek 基于已有知识、用户填写的企业身份、官网地址和 JD 内容进行归纳。

- 页面固定提示“基于模型已有知识，非实时联网结果”。
- 不展示伪造的官方来源、发布日期或链接。
- 结论标签区分“模型已有知识”和“系统推断”。
- DeepSeek 无法确认的信息返回“现有知识不足”，对应字段不生成肯定判断。
- 用户填写的官网仅用于企业识别和提醒用户自行核对，不由服务端抓取网页。
- 企业知识不足不会影响已有 JD 适配结果、回答优化或模拟面试入口。

## 页面调整

### 岗位方向

- “市场岗位画像”改为“岗位要求与经历对照”。
- “生成新版岗位分析”改为“生成岗位分析”。
- “正在联网分析”改为“正在整理岗位要求并对照经历”。
- 删除来源列表、联网状态和联网失败提示。
- 旧记录若包含来源信息仍可读取，但页面不再展示和依赖来源。

### 服务设置

- 页面标题、字段、帮助文案和状态检测全部改为 DeepSeek。
- 默认模型显示 `deepseek-v4-flash`，允许手动改为 `deepseek-v4-pro`。
- 保存后使用最小请求验证鉴权与模型可用性。

### 面试研究

- 删除“正在联网研究”“只重新进行企业研究”和来源抽屉等联网语义。
- 改为“正在整理企业与岗位信息”“重新生成企业画像”。
- 显示非实时知识提示和信息不足状态。

## 数据兼容

- 现有 `marketAnalysis`、`InterviewResearch` 和历史 JD 结构不做破坏性迁移。
- 新生成的岗位分析允许 `sources` 为空，并固定记录 `knowledgeMode: "model-knowledge"`。
- 旧联网分析记录仍可打开；重新生成后替换为非联网版本。
- 本地浏览器数据、历史 JD 图标和经历档案不清空。

## 错误与超时

- DeepSeek 鉴权、限流、额度、超时、取消、上游异常和 JSON 格式异常分别显示可理解提示。
- 常规分析默认 45—60 秒，JD 和企业画像可放宽到 90—120 秒，模拟面试单轮保持较短上限。
- 超时只结束当前任务，已保存的经历、JD、分析结果和面试轮次不丢失。
- 不自动无限重试；格式修复最多一次，长任务超时交由用户手动重试。

## 测试与验收

- 全部 API 请求只访问 DeepSeek，不再访问 DashScope。
- 岗位分析不产生任何联网搜索请求。
- 企业研究在无来源时仍能生成受约束的模型知识结果，信息不足时如实返回。
- 岗位要求逐条显示 3—4 条短证据，页面不出现大段档案搬运。
- 设置页可保存、检测和清除 DeepSeek Key。
- 旧数据仍可读取，旧千问 Key 不会作为 DeepSeek Key 发送。
- 全量测试、类型检查、Worker 测试和生产构建通过后，再提供本地浏览器验收；验收确认后发布。
