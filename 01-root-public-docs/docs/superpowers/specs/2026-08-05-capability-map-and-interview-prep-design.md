# 能力星图与面试准备分栏设计

## 目标

将能力星图从“能力、工具、缺口、面试建议”混在一页，调整为两个清晰的网页栏目：

- **能力星图**：回答“我有什么能力和独立资产”。
- **面试准备**：回答“我还缺什么、面试会怎么追问、我该如何准备”。

保留当前本地 IndexedDB 数据和证据展开能力，不改变既有经历、工具、语言、证书数据的存储方式。

## 页面结构

### 能力星图

1. 顶部摘要：已确认能力数量、证据数量、覆盖经历数量、待补能力数量。
2. 工作能力双栏：
   - 左侧为六类能力能量条：专业能力、统筹执行、策略思考、AI 应用、数据与复盘、沟通协作。
   - 每项能力展示分数/状态、证据数、覆盖经历数、证据强度，并保留“查看证据”。
   - 右侧为六维雷达图；六个顶点直接显示中文分类标题和分数，不能依赖颜色图例才能理解。
3. 独立资产栏：工具与软件、语言能力、证书与等级考试单独展示，不混入工作能力分数。
4. 网页响应式：桌面端能力能量条与雷达图并排；窄屏自动上下排列；长标题和证据摘要不溢出。

### 面试准备

新增独立导航栏目/页面，复用当前 JD 面试研究和模拟面试入口，但不把缺口内容塞回能力星图。

1. 能力缺口卡：
   - 缺少的能力/证据；
   - 为什么对目标岗位重要；
   - 具体补充步骤（通常 2—3 步）；
   - 可产出的材料或案例；
   - 可直接口述的面试表达模板；
   - 去补充经历、加入准备清单、标记已掌握。
2. 岗位思维提示卡：
   - 面试官正在验证什么；
   - 用户需要准备的证据；
   - 应避免的空泛或高风险表述；
   - 自测问题/可能追问。
3. 首批思维维度：个人贡献边界、数据真实性与口径、优先级与取舍、冲突与影响力、从产出到业务结果、跨岗位迁移、AI 使用责任、求职动机。
4. 能力缺口和岗位思维均优先使用真实已确认档案生成；证据不足时显示“待补充”，不编造经历或指标。

## 数据与计算

- 继续复用 `buildCapabilitySummaries` 的证据 ID、经历 ID 和资料 ID。
- 在领域层增加能力分类映射：将已有确认 claim 和独立资料归入六类工作能力或独立资产。
- 能量条分数由证据数量、覆盖经历数量、结果/贡献字段完整度、证据置信度综合计算，并保留“证据不足”状态；分数只用于个人准备，不包装成录用结论。
- 雷达图读取六类聚合分数；缺少某类证据时显示低覆盖/待补，不隐藏该类。
- 面试准备页的缺口和思维提示通过现有 AI 服务生成时必须携带真实证据 ID，前端只显示清理后的最终文案。

## 视觉语言

- 延续现有暖纸张底色、粗描边、轻微不规则圆角和油画棒色块。
- 能量条使用珊瑚、鼠尾草绿、奶油黄三组状态色；颜色不是唯一信息来源，文字状态必须同时存在。
- 雷达图使用手绘虚线网格、粗描边和顶点中文标签。
- 面试准备页使用纸片式卡片、编号步骤和可勾选动作，降低抽象感。

## 状态与兼容

- loading、empty、error、partial 状态沿用现有页面模式。
- 旧本地数据没有新增能力分类时，按现有 claim 文本进行保守映射；无法映射的条目仍显示在“其他已确认能力”或证据列表中，不丢失。
- 没有能力缺口数据时，显示“补充更多经历后生成”，不显示虚构建议。

## 测试与验收

- 为能力分类、分数、工具/语言分离和证据计数增加领域测试。
- 为六类雷达数据和缺口/思维卡渲染增加页面测试。
- 检查桌面宽屏、窄屏布局，以及长中文标题不溢出。
- 运行现有 typecheck、Vitest、Worker 测试和生产构建；不提交真实简历或 API Key。
